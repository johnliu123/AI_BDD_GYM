# UI Plan：相簿整理器

- **來源規格**：[功能規格：相簿整理器](../specify/templates/spec.example.md)
- **系統分析計畫**：[plan.md](../system-analysis/templates/plan.example.md)
- **互動雛形**：[prototype.example/](prototype.example/index.html)（本 skill 範例；實際功能目錄為同層 `prototype/`）

## 範疇

- **分析邊界**：前端與使用者介面；不含 HTTP API、MySQL 或私有目錄實作。
- **涵蓋需求部位**：瀏覽相簿與日期分組、匯入照片、預覽、排序、本機使用限制。
- **設計前提（來自 plan／規格）**：
  - 相簿依拍攝日期分組；缺日期照片歸入唯一「日期未知」相簿。
  - 瀏覽器只顯示預覽，不提供原始檔下載。
  - 上傳可逐檔進行；每檔成功或失敗須分別回饋。
  - 排序變更成功後立即反映；重新整理後順序須與伺服器一致（雛形以 localStorage 模擬持久化）。

## 畫面與流程

| 畫面 | 檔案 | 目的 | 主要區塊 |
|---|---|---|---|
| 相簿列表 | `index.html` | 依日期瀏覽 | 標題列、相簿卡片、匯入入口 |
| 相簿詳情 | `album.html` | 平鋪預覽與排序 | 返回、格狀照片、排序提示 |

### 瀏覽相簿與照片

- **觸發**：開啟應用（`index.html`）。
- **步驟**：相簿列表 → 點選相簿 → `album.html` 格狀預覽 → 返回列表。
- **追溯**：FR-001、FR-002、User Story 1

### 匯入照片

- **觸發**：列表或詳情頁「匯入」。
- **步驟**：選檔 → 逐檔假上傳與 toast／列表示意 → 更新對應相簿計數（雛形寫入假資料）。
- **追溯**：FR-001、FR-010、User Story 1

### 排序

- **觸發**：詳情頁進入排序模式。
- **步驟**：點選兩張照片交換順序（流程級模擬拖放）→ 成功 toast → 重新整理仍保留（localStorage）。
- **追溯**：User Story 2

### 狀態與邊界（雛形須可見）

- 空相簿、上傳失敗 toast、排序失敗還原（雛形可選觸發示範檔）。

## 實作

- **雛形技術**：靜態 HTML + 共用 `assets/styles.css`、`assets/app.js`；假資料與 localStorage，不呼叫真 API。
- **正式前端（對齊 plan）**：Vite 單頁或與雛形相同的多頁路由；元件化相簿列表、格狀、上傳佇列 UI、排序模式。
- **視覺方向**：溫暖中性色、大圓角卡片、清晰層級；照片格以一致比例裁切；操作回饋用 toast 與 inline 狀態，不用說明型文案區塊。
- **非目標**：帳號、分享、雲端、原始檔下載、後端 Origin 實作細節。

## 驗證

- **Markdown**：每個需求部位在「畫面與流程」有對應；無 API／schema 越界描述。
- **雛形**：
  - 以瀏覽器開啟 `prototype/index.html`，走完列表 → 詳情 → 匯入（假）→ 排序 → 重新整理仍保留順序。
  - 確認頁面為產品 UI，而非規格說明或 README 式排版。
- **與 plan 一致**：預覽-only、逐檔回饋、unknown 相簿可從列表進入。
