# Rule 1 - 已確認的資安弱點必須以 CVSS v4.0 定性量表評估嚴重度

- Level: `MUST`
- 僅對「已確認」層級的資安弱點套用 CVSS v4.0；「疑似」與「建議」不評 CVSS 分數，僅標記暫定嚴重度並註明「未評分，待確認後補」。
- 嚴重度對照 CVSS v4.0 官方定性量表：Critical 9.0–10.0、High 7.0–8.9、Medium 4.0–6.9、Low 0.1–3.9、None 0.0。
- 若團隊未使用完整 CVSS 計算工具，可用簡化估算（參考影響範圍與利用難度），但報告中必須標註「簡化估算，非正式 CVSS Base Score」，不可宣稱是正式 CVSS 分數。

## Good Example

- 這個例子是好的，因為標示清楚是簡化估算並說明理由，沒有冒充正式 CVSS 計算結果。

````text
F1 | 已確認 | SQL Injection | High（簡化估算：未驗證輸入可讀取整表資料，無需權限即可觸發）
````

## Bad Example

- 這個例子是壞的，因為憑感覺給分卻宣稱是正式 CVSS 分數，未附任何指標依據。

````text
F1 | 已確認 | SQL Injection | CVSS 8.5（正式分數）
````

# Rule 2 - 非資安類問題不得套用 CVSS，須用獨立業界慣例嚴重度判準

- Level: `MUST`
- Bug／邏輯問題／效能問題／程式碼品質問題屬於非資安類，CVSS 僅適用於資安弱點，不可套用於這些類別，避免混淆正式標準與一般工程判斷。
- 非資安類問題改用下列業界慣例（非正式標準，須在報告中註明為本專案採用之嚴重度慣例）：
  - **CRITICAL**：會造成資料遺失、資料錯誤寫入、服務中斷或無法回復的狀態，且影響核心功能或大量使用者。
  - **HIGH**：造成功能錯誤或資料不一致，但有限定觸發條件或影響範圍，無資料遺失風險。
  - **MEDIUM**：影響次要功能、邊界情況或低頻率情境，不影響主流程。
  - **LOW**：僅影響可讀性、維護性、效能的輕微改善空間，不影響功能正確性。

## Good Example

- 這個例子是好的，因為清楚區分資安與非資安問題各自套用不同判準，且非資安問題說明影響範圍。

````text
F1（資安）| SQL Injection | CVSS High（簡化估算）
F2（Bug） | 刪除訂單後未釋放鎖定資源，造成相同使用者無法再次下單 | CRITICAL（本專案 Bug 嚴重度慣例：核心下單流程阻斷）
````

## Bad Example

- 這個例子是壞的，因為把一般邏輯 Bug 也套用 CVSS 分數，混淆了正式標準的適用範圍。

````text
F2（Bug）| 刪除訂單後未釋放鎖定資源 | CVSS 7.0
````

# Rule 3 - 每筆已確認資安弱點須標註對應 CWE ID

- Level: `SHOULD`
- 已確認的資安弱點應標註對應的 CWE ID（可取自 SAST 工具的 rule tag，或依 CWE 官方描述人工比對），作為分類依據與可追溯的官方對應。
- 若找不到精確對應的 CWE，標註最接近的分類並註明「近似對應，非精確比對」，不應留白。

## Good Example

- 這個例子是好的，因為標註了具體 CWE 編號，並與弱點內容相符。

````text
F1 | SQL Injection | CWE-89
````

## Bad Example

- 這個例子是壞的，因為完全沒有標註 CWE，讀者無法對照官方分類。

````text
F1 | SQL Injection | （無）
````

# Rule 4 - 修正優先順序依「嚴重度 × 實際可觸發性」排序，不單用嚴重度排序

- Level: `MUST`
- 修正優先順序必須同時考慮嚴重度與實際可觸發性（是否需要特殊權限、是否對外暴露、觸發頻率），不可只依嚴重度欄位數字由高到低排序。
- 高嚴重度但需極罕見前置條件（如需先取得內部管理權限）才能觸發者，可排在中嚴重度但任何未驗證使用者皆可觸發的問題之後；排序調整須在報告中寫明理由。

## Good Example

- 這個例子是好的，因為說明了為何嚴重度較低的項目優先修正：可觸發性更高。

````text
修正順序：
1. F2（HIGH，任何未登入使用者皆可觸發）
2. F1（CRITICAL，僅限已取得管理員權限的內部帳號才可觸發，暴露面極小）
理由：F2 攻擊面遠大於 F1，優先修復降低整體風險。
````

## Bad Example

- 這個例子是壞的，因為單純依嚴重度欄位排序，未考慮實際可觸發性。

````text
修正順序：F1（CRITICAL）優先於 F2（HIGH），因為 CRITICAL 分數比較高。
````
