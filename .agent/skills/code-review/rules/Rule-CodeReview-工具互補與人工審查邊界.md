# Rule 1 - 跨工具重複的候選項必須合併為單一 finding 並保留所有來源

- Level: `MUST`
- 多個工具（或同一工具的 Lint/SAST/AI 結果）指向同一檔案、相近行號、相同根因時，必須合併為一筆 finding，不可各自重複列出。
- 合併時必須保留每個原始來源的工具名稱與規則 ID，供追溯；不可只保留其中一個來源而捨棄其餘證據。

## Good Example

- 這個例子是好的，因為合併後仍列出所有來源工具與規則 ID，沒有遺失任何一個。

````text
F1 | orders.py:42 | SQL Injection
  來源：Semgrep(sql-injection-raw-query), CodeQL(py/sql-injection)
````

## Bad Example

- 這個例子是壞的，因為同一根因被列成兩筆獨立 finding，且各自只記錄一個來源。

````text
F1 | orders.py:42 | Semgrep 標記 SQL Injection
F2 | orders.py:42 | CodeQL 標記 SQL Injection
````

# Rule 2 - 商業邏輯、授權設計與跨模組一致性問題，不得僅依賴工具判定是否成立

- Level: `MUST`
- 下列類型問題即使沒有任何工具標記，也必須在人工／AI 輔助審查階段主動追蹤，且即使工具有標記，仍須人工確認是否符合業務情境才能列為已確認：
  - 商業邏輯是否符合需求（例如折扣計算、流程順序、狀態機轉換是否合理）。
  - 授權設計本身是否合理（例如角色權限劃分、資源擁有權檢查邏輯），而非僅檢查是否「有」權限檢查。
  - 跨模組／跨服務的一致性（例如同一業務規則在前後端或多個服務重複實作卻邏輯不一致）。
- 自動化工具對這三類問題的覆蓋率低，缺少工具警告不代表沒有問題。

## Good Example

- 這個例子是好的，因為即使沒有工具警告，仍主動追蹤角色權限設計是否合理並發現問題。

````text
人工審查發現：editArticle() 僅檢查使用者是否登入，未檢查文章擁有者是否為當前使用者，
任何登入使用者皆可編輯他人文章；無任何 SAST 工具標記此問題。
````

## Bad Example

- 這個例子是壞的，因為只因沒有工具警告就認定授權設計沒有問題。

````text
SAST 掃描 editArticle() 沒有任何警告，判定授權設計沒有問題。
````

# Rule 3 - AI 產出的 finding 升級為已確認前，須與另一獨立來源交叉確認

- Level: `MUST`
- AI 輔助審查提出的 finding，升級為「已確認」前，必須經過以下至少一種獨立交叉確認：人工實際追蹤程式碼路徑、靜態分析工具的對應規則命中、或可重現的測試案例。
- 不可僅憑 AI 的解釋文字本身作為確認依據，因 AI 對程式碼變更的描述有相當比例與實際程式碼不符的風險（幻覺），且提示詞越詳細、要求越多步驟解釋，AI 誤判正確程式碼為有問題的機率可能反而上升。

## Good Example

- 這個例子是好的，因為 AI 的判斷有經過人工實際追蹤程式碼確認後才升級。

````text
AI 提示：checkPermission() 疑似缺少角色檢查。
人工追蹤：確認該函式確實只檢查 session 是否存在，未檢查 role 欄位 → 升級為已確認。
````

## Bad Example

- 這個例子是壞的，因為單純接受 AI 的說法就直接列為已確認，沒有任何交叉確認。

````text
AI 說 checkPermission() 有問題，所以直接列為已確認的資安弱點。
````

# Rule 4 - 僅覆蓋單一工具語言／框架範圍的程式碼，須明確標示為未掃描

- Level: `SHOULD`
- 若專案包含選用工具不支援的語言、框架或檔案類型（例如 SAST 工具未涵蓋的範本引擎、設定檔格式），須在報告的「已載入／掃描範圍」中明確列出未涵蓋部分，不應讓讀者誤以為全專案已完整掃描。
- 未涵蓋部分若屬高風險區域（如存取控制設定檔），應標記為待人工審查項目，而非略過不提。

## Good Example

- 這個例子是好的，因為明確說明哪些檔案類型未被工具掃描，並標記需要人工審查。

````text
掃描範圍：*.py, *.js 已由 Semgrep 掃描；*.yaml 設定檔不在 Semgrep 規則涵蓋範圍內，
已標記為待人工審查項目（見 F9 設定檔權限疑慮）。
````

## Bad Example

- 這個例子是壞的，因為完全沒提及設定檔未被掃描，讓讀者誤以為已全面涵蓋。

````text
已完成全專案安全掃描，無其他待辦事項。
````
