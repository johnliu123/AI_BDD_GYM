# Rule 1 - P0／P1 只代表「已確認」問題的兩級處理優先順序，不得混入疑似或建議層級

- Level: `MUST`
- 🔴 **P0（必須修正）** = 確認層級為「已確認」且嚴重度為 `CRITICAL` 或 `HIGH`。
- 🟡 **P1（建議修正）** = 確認層級為「已確認」且嚴重度為 `MEDIUM` 或 `LOW`。
- 「疑似（Suspected）」層級一律另列於「⏳ 待確認疑似問題」區塊，**不得**貼 P0／P1 標籤；因為尚未人工驗證存在，貼上 P0／P1 會誤導讀者以為已確認且須立即處理。
- 「建議（Suggestion）」層級一律另列於「💡 其他改善建議」區塊，且維持 `rules/Rule-CodeReview-證據與確認層級.md` Rule 4 的用詞限制（不可用「弱點」「Bug」等字眼）。
- 每筆快速摘要項目必須標註原始 finding ID，可追溯回「Findings 詳情」完整記錄；完整報告中屬「已確認」且嚴重度 `CRITICAL`／`HIGH` 的項目，必須全部出現在 P0 摘要，不可遺漏；反之摘要也不可出現完整報告找不到對應 ID 的項目。

## Good Example

- 這個例子是好的，因為已確認的兩筆分別歸入 P0，疑似項目維持獨立區塊未被貼上 P1 標籤，建議項目也維持獨立區塊。

```text
🔴 P0：F1（SQL Injection，已確認/HIGH）、F2（lodash 弱點，已確認/HIGH）
⏳ 待確認疑似問題：F3（N+1 Query，疑似/MEDIUM 暫定）
💡 其他改善建議：S1（函式職責過多，建議）
```

## Bad Example

- 這個例子是壞的，因為把尚未人工確認的疑似項目也貼上 P1 標籤，讀者會誤以為已確認。

```text
🟡 P1：F3（N+1 Query，疑似，尚未人工確認觸發規模）
```

# Rule 2 - P0／P1 摘要項目以「❌ 目前 vs ✅ 建議」程式碼對比呈現，且可追溯回完整 diff

- Level: `SHOULD`
- 每個 P0／P1 項目應包含：標題（含檔案路徑與行號）、❌ 目前程式碼片段、✅ 建議程式碼片段、簡短「影響範圍」條列。
- 若建議修正需要多檔案／多步驟調整，無法用單一 code block 完整表達時，❌／✅ 可改為一句話文字描述「目前行為」與「建議行為」，但必須在完整 Findings 詳情該筆記錄中補上完整 diff，不可為了塞進快速摘要而省略必要的修正步驟。
- 「影響範圍」條列必須列出實際受影響的檔案／模組，而非抄錄問題描述本身。

## Good Example

- 這個例子是好的，因為清楚對比現況與建議，並列出具體受影響的其他檔案。

```text
❌ 目前：complete() 直接執行成功流程
✅ 建議：成功流程移至 next()，complete() 僅收尾
影響範圍：
- fpcrt210-esso-racf-login.component.ts：登入失敗可能誤執行成功流程
- fpcrt210-racf-login.service.ts：F07/F08/Fpcrt240 共用此登入視窗，錯誤會被放大到所有入口
```

## Bad Example

- 這個例子是壞的，因為只貼代碼沒有任何影響範圍說明，讀者無法判斷修正的必要性與波及面。

```text
把 complete 改成 next 就好了。
```

# Rule 3 - 檢查清單命中項目仍須完整走證據與確認層級流程，不可憑清單直接判定

- Level: `MUST`
- `references/Reference-前後端檢查清單.md` 的勾選結果僅是 Phase 4／Phase 5 的追蹤起點，不是自動結論；命中清單項目後，仍須依 `rules/Rule-CodeReview-證據與確認層級.md` 人工追蹤程式碼路徑或重現後，才能升級為「已確認」。
- 清單未涵蓋到的程式碼區域不可因此略過分析；也不可宣稱「已依清單確認無問題」等同「已完整審查該區域」，清單文件本身已聲明不窮盡，報告引用清單結果時須保留此限制。

## Good Example

- 這個例子是好的，因為清單命中後仍走了人工追蹤才升級為已確認，並明確說明清單本身的侷限。

```text
依檢查清單 B3「complete 是否誤執行成功流程」命中 → 人工追蹤 ScpRxHttpService filter 邏輯，
確認 SCP message 型錯誤確實會被過濾掉，仍進入 complete() → 升級為已確認。
本次清單未涵蓋前端 UI 元件樣式問題，未納入本次分析範圍。
```

## Bad Example

- 這個例子是壞的，因為只因清單命中就直接列為已確認，且宣稱清單已涵蓋全部問題。

```text
依清單 B3 勾到這一項，所以確定是 Bug，而且已經用清單審查過全部程式碼，沒有其他問題了。
```
