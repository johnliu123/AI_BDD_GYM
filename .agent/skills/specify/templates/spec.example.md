# 功能規格：相簿整理器

**功能分支**：`001-photo-album-organizer`

**建立日期**：2026-09-25

**狀態**：草稿

**輸入**：使用者描述："幫我開發一個應用程式，這個程式可以幫助我將照片整理到不同的相簿中，相簿要按照日期分組。分組完之後呢，我可以在我的主頁面上面透過拖放來重新排列這些照片。那相簿絕對不會嵌套在其他相簿中。在每個相簿中呢，照片會以平鋪式的界面進行預覽。"

## 商業規則 *(必要)*

- **BR-001**: 相簿為平面結構，不得嵌套在其他相簿中。（對應需求：**FR-005**）
- **BR-002**: 日期分組以日曆「日」為單位；拖放僅調整同一相簿內展示順序，不得因拖放改變照片的日期歸屬或相簿 membership。（對應需求：**FR-003**、**FR-007**）
- **BR-003**: 缺少可用拍攝日期的照片須歸入唯一且明確標示的「日期未知」相簿，不得捨棄或任意指定日期。（對應需求：**FR-002**）
- **BR-004**: 上傳時間僅作稽核／排序輔助，不得替代拍攝日期作為分組依據。（對應需求：**FR-001**、**FR-002**）

## 使用者情境與測試 *(必要)*

### 使用者故事 1 - 建立日期分組的相簿 (優先順序：P1)

使用者希望將照片整理成依日期分組的相簿，這樣可以以時間線的方式快速瀏覽和管理自己的影像資料。系統需要在不失去可讀性的前提下，讓相簿依照拍攝日期自然分組，避免使用者手動逐張分類。

**為何這個優先順序**：這是本功能的核心價值，若日期分組失敗，使用者將無法有效整理大量照片，也無法完成後續的排列與預覽體驗。

**獨立測試**：可由使用者匯入多張不同日期的照片，檢查相簿是否依日期正確分組，並確認每張照片均能在對應相簿中找到。

**驗收情境**：

1. **Given** 使用者匯入多張來自不同日期的照片，**When** 他啟動整理流程，**Then** 系統會將照片依日期分組到對應相簿中。
2. **Given** 同一日期內有多張照片，**When** 使用者查看該相簿，**Then** 系統會在同一相簿中顯示所有該日期的照片。
3. **Given** 使用者新增新照片，**When** 新照片帶有不同日期資訊，**Then** 系統會將它放入正確的日期相簿，而不是混入其他分組。

**功能需求（FR）**：

- **FR-001**: 系統必須讓使用者匯入照片，並將每張照片依其拍攝日期分組到不同相簿中；日期分組以日為單位。
- **FR-002**: 系統必須以照片的拍攝日期自動建立或歸屬相簿；缺少可用拍攝日期的照片必須歸入唯一且明確標示的「日期未知」相簿。
- **FR-010**: 系統必須允許使用者將新照片加入既有相簿，並在其日期對應的相簿中正確呈現。
- 全域需求參照：**FR-005**、**FR-007**。

**非功能需求（NFR）**：本故事未明確提出專屬 NFR。

---

### 使用者故事 2 - 以拖放方式重新排列照片 (優先順序：P2)

使用者希望在主頁面的相簿照片區域重新安排照片順序，讓最重要的照片能置於前排或依偏好排序。拖放操作需要直覺且可預測，讓使用者能在視覺上快速重排照片，而不需要重新整理整個相簿。

**為何這個優先順序**：排列照片是整理工作完成度的重要延伸，能直接影響使用者對相簿的可用性與滿意度。

**獨立測試**：使用者可從主頁面拖曳照片到新位置，檢查排序是否保留並立即反映在主頁面與該照片所屬相簿中。

**驗收情境**：

1. **Given** 使用者位於主頁面，**When** 他將一張照片拖放到同一相簿的另一位置，**Then** 系統會更新該相簿內的順序並立即呈現新的排列。
2. **Given** 使用者在主頁面將照片拖放到相簿末端，**When** 操作完成，**Then** 系統會將該照片放置在預期的位置，且不影響其他照片。
3. **Given** 使用者在拖曳過程中取消操作或將照片拖到無效區域，**When** 他結束拖曳，**Then** 系統不會改變原本的排列或照片所屬相簿。

**功能需求（FR）**：

- **FR-003**: 系統必須在主頁面提供照片拖放排序，並立即反映同一相簿內的新順序；排序不得改變照片的日期分組。
- 全域需求參照：**FR-007**。

**非功能需求（NFR）**：

- **NFR-001**: 拖放操作必須直覺且可預測，讓使用者能理解並確認照片的新排列結果。

### 使用者故事 3 - 以平鋪式預覽瀏覽相片 (優先順序：P3)

使用者需要在每個相簿中以平鋪式介面預覽照片，方便檢視大量圖片並快速選擇要刪除、編輯或調整順序的內容。預覽畫面需符合直觀的瀏覽體驗，避免層級嵌套或難以操作的檢視模式。

**為何這個優先順序**：預覽是相簿內容檢視與後續操作的入口，雖不是最前端的產出，但會直接影響整體使用效率與明確性。

**獨立測試**：使用者開啟某個相簿時，可直接檢視所有照片的平鋪預覽，不需點入其他巢狀資料夾。

**驗收情境**：

1. **Given** 使用者開啟某個相簿，**When** 頁面載入完成，**Then** 系統會以平鋪式卡片或格狀方式顯示所有照片。
2. **Given** 相簿中有多張照片，**When** 使用者捲動瀏覽，**Then** 系統會持續顯示照片而不產生相簿巢狀結構。
3. **Given** 使用者切換到其他相簿，**When** 他回到該相簿，**Then** 系統會維持其既有的排列與預覽配置。

**功能需求（FR）**：

- **FR-004**: 系統必須允許使用者在相簿內以平鋪式視覺方式預覽照片。
- **FR-006**: 系統必須在主頁面中以清楚可辨識的方式呈現所有平面相簿及其照片，並提供相簿間的瀏覽入口。
- **FR-008**: 系統必須在相簿為空時提供明確的空狀態提示，協助使用者理解未來的操作方式。
- **FR-009**: 系統必須在相簿內以平鋪式格狀預覽顯示照片，且每張照片都能被辨識，不得要求使用者進入巢狀相簿才能瀏覽。
- 全域需求參照：**FR-005**。

**非功能需求（NFR）**：本故事未明確提出專屬 NFR。

### 邊界情況

- 當相簿內沒有任何照片時，系統應顯示明確的空狀態，並讓使用者知道可匯入照片。
- 當照片缺少可用的拍攝日期時，系統應將其放入明確標示的「日期未知」相簿，而不是捨棄照片或任意歸類。
- 當多張照片來自相同日期但不同時間點時，系統應先依拍攝時間排序；若時間相同或不存在，則維持匯入順序。
- 當使用者在拖曳過程中發生中斷或重新整理頁面時，系統應保留最近一次成功完成的排列。
- 當照片被拖到另一個日期相簿時，系統不得因拖放而改變照片的日期分組；無效的跨相簿拖放應被拒絕並保留原位置。

## 全域需求 *(必要)*

本區只列出適用於多個 User Story 的跨故事需求，每項需求只在此保留一份正式內容。各 User Story 以需求 ID 參照適用的全域需求；只適用於單一 User Story 的 FR/NFR 則列在該故事底下。

### 功能需求（FR）

- **FR-005**（適用於使用者故事 1、3）: 系統必須避免相簿嵌套在其他相簿中，確保相簿結構為平面結構。
- **FR-007**（適用於使用者故事 1、2）: 系統必須保持相簿內照片的排序與日期分組資訊在成功操作、取消操作與頁面重新整理後一致且可預測。

### 非功能需求（NFR）

本範例未明確提出適用於多個 User Story 的全域 NFR。

### 主要實體 *(若功能涉及資料則納入)*

- **使用者**：使用此應用程式的個人，負責管理照片與相簿整理。
- **照片**：具有日期資訊與內容資料的影像檔案，會被分組與重新排列。
- **相簿**：依日期分類的集合，作為照片管理的主要單位。
- **日期分組**：依照片拍攝日期所形成的邏輯分類，決定相簿歸屬。
- **排列順序**：相簿內照片展示順序，由使用者在主頁面上的拖放操作所定義，並與該相簿一致。

## 成功標準 *(必要)*

### 可衡量成果

- **SC-001**: 使用者在匯入 100 張以內的照片後，能在 3 分鐘內完成日期相簿的初步整理。
- **SC-002**: 90% 以上的使用者能在首次嘗試時，從主頁面完成將照片拖放到目標順序的操作。
- **SC-003**: 99% 以上具有可用拍攝日期的照片能正確出現在其對應日期相簿中，且沒有照片遺失或重複。
- **SC-004**: 使用者能在不進入巢狀相簿的情況下，完成所有相簿內照片的瀏覽與排序。
- **SC-005**: 在空相簿、取消拖放、重新整理頁面以及多日期混合資料的情況下，95% 以上的操作結果與使用者預期一致。

## 假設

- 使用者已具備一批待整理的照片，且有能力匯入或上傳至應用程式。
- 相簿整理的主要目標是依日期分類，而非依人、地點或標籤分類。
- 系統可依照片內建的拍攝日期資訊判定其分組；無日期照片放入「日期未知」相簿，且相簿不需要支援多層套疊結構。
- 日期相簿使用日曆日期作為識別，不因使用者拖放照片而改變；拖放只調整同一相簿內的展示順序。
- 這個版本聚焦於相簿管理與照片排序，不包含進階編輯、AI 自動標註或雲端同步等擴充功能。
