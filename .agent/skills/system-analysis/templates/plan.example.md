**結構決策**：採用最精簡的 `frontend/` + `backend/` 雙專案結構。前端只以 Vite 建置與本機代理 API；後端以 Express 路由、少量服務函式及 mysql2 直接存取 MySQL。影像檔案置於設定的私有資料目錄（預設 `data/`），不得放入 `frontend/public/` 或任何可直接列目錄的靜態路徑。

## 設計決策

- 相簿以 EXIF 拍攝日建立；缺日期的照片歸入唯一 `unknown` 相簿。擷取日期使用原始 EXIF 的本地時間與可選時區偏移，不猜測時區、不以上傳時間補值。
- 新相簿內照片預設依拍攝時間排序；同時間或無拍攝時間時依匯入先後穩定排序。拖放成功後相簿採手動順序；後續照片加入手動排序相簿時附加於末端。
- 上傳與排序由 API 持久化；重新整理後以伺服器資料還原順序。每個上傳請求僅一檔，前端可逐檔送出並逐檔回報失敗。
- MySQL transaction 用於建立相簿／照片中繼資料及整批順序更新；磁碟檔案先寫入暫存位置，資料庫失敗時清理暫存／已移動檔案。
- 因 MySQL 不支援延後檢查唯一索引，重排時先在 transaction 內把位置移至不衝突的暫存範圍，再寫入 `0..n-1` 最終位置。
- 保留原始影像於私有目錄供本機服務生成預覽；瀏覽器只使用經縮放且移除 EXIF 的預覽 API。第一版不提供原始檔下載。
- 所有變更請求驗證精確的前端 Origin；僅綁定 loopback 並不足以單獨防止惡意網站對本機 API 發送請求。


## 分析流程規劃

本段只規劃後續系統分析的範圍與排程，不在此處產生各端點的分析結論或設計細節。先從使用者需求拆出需求部位，再標記每個需求部位涉及的技術端點；以需求間的先後依賴決定 Wave。每個端點至少安排一個分析步驟；只有前置分析結果不會阻礙其工作的端點，才排在同一 Wave 平行處理。排程完成後，System Analysis 會依 Wave 順序委派各端點專責 Skill 實際分析；每項工作須標示負責 Skill（含 skill id）、輸出產物路徑、必要前置產物及分析邊界。

### 相簿整理器：需求部位與端點盤點

| 需求部位 | 涉及的技術端點 |
|---|---|
| 瀏覽相簿、查看日期分組及日期未知的照片 | 前端、後端 API、MySQL |
| 匯入照片、驗證格式與限制、讀取拍攝日期 | 前端、後端 API、私有檔案儲存、MySQL |
| 顯示不含 EXIF 的照片預覽 | 前端、後端 API、私有檔案儲存 |
| 拖放排序並在重新載入後保留順序 | 前端、後端 API、MySQL |
| 僅限本機使用並避免公開原始影像 | 前端、後端 API、私有檔案儲存 |

本次實際端點為 **前端、後端 API、MySQL、私有檔案儲存**；需求未包含金流、手機 App、雲端或第三方服務，因此不將它們列入本相簿計畫。

### 相簿整理器：分析 Wave 排程

Wave 的切分依分析工作對其他端點結果的需求，而非單純按端點清單排序。每個端點安排獨立分析步驟；同一 Wave 中的端點分析可平行委派。

#### Wave 1：先取得前端流程與持久化邊界

以下端點分析可平行進行，作為後續後端 API 分析的輸入：

1. **前端分析（UI Plan）**：依相簿瀏覽、匯入、預覽與排序等需求部位，規劃 UI 與操作流程，產出 `ui-plan.md` 及可操作的 `prototype/` HTML 雛形。
2. **MySQL 分析（Data Plan）**：依日期分組、照片中繼資料及排序持久化等需求部位，分析資料庫端點，產出 `data-model.dbml`（DBML `Table`／索引／`Ref`）。
3. **私有檔案儲存分析（Data Plan）**：依原圖、預覽圖、暫存及私有存取等需求部位，分析檔案儲存端點，整合至同一 `data-model.dbml`（`Project Note` 或註解分節）。

#### Wave 2：依前置結果分析後端 API

1. **後端 API 分析（API Plan）**：依 Wave 1 的使用者操作流程、資料持久化需求及檔案生命週期，分析後端 API 端點及其與其他端點的整合邊界，產出 OpenAPI 契約 `contracts/http-api.yaml`。

### Wave 排程示意：包含金流的另一種需求

以下為說明如何按需求依賴排程的示意，**不是相簿整理器的需求或端點**：

- **端點盤點**：前端、金流端、後端、資料庫端。
- **Wave 1（平行）**：
  1. 前端分析：先依需求分析 UI/UX 流程，讓後續後端分析可依據使用者操作與互動流程。
  2. 金流端分析：查核金流端的相關文件與介面；若此工作與前端分析沒有前置依賴，可同波進行。
  3. 兩項工作分別委派給負責的分析 Skill，並由兩個 sub-agent 平行執行。
- **Wave 2（平行）**：
  1. 後端分析：依 Wave 1 的前端流程與金流端分析結果進行。
  2. 資料庫分析：依需求中的資料持久化部位進行，與後端分析同波平行處理。

此示意中的 Wave 代表依賴順序與可平行工作的分組；不描述各分析 Skill 的內部方法，也不預先填入分析結論。
