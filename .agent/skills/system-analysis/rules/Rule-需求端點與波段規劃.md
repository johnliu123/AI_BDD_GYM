# Rule 1 - 技術端點必須從需求部位盤點並追溯

- Level: `MUST`
- 先將使用者需求拆成可辨識的功能、品質或限制部位，再為每個需求部位標記涉及的技術端點；不可只依常見架構列一份未連結需求的端點清單。
- 端點類型須由需求推導，不限於前端、後端、資料庫；需求涉及時也應考慮檔案儲存、金流、手機、硬體、雲端或第三方服務。
- 端點盤點必須涵蓋需求部位涉及的所有端點，且每個列出的端點至少對應一個分析排程步驟。

## Good Example

- 這個例子是好的，因為照片匯入需求明確對應到處理操作、API、持久化及影像檔案的端點。

```md
| 需求部位 | 涉及的技術端點 |
|---|---|
| 匯入照片並保留中繼資料 | 前端、後端 API、資料庫、私有檔案儲存 |

端點清單：前端、後端 API、資料庫、私有檔案儲存。
```

## Bad Example

- 這個例子不合格，因為同一項照片匯入需求涉及私有檔案儲存，端點盤點卻遺漏該端點，也沒有為它安排分析步驟。

```md
| 需求部位 | 涉及的技術端點 |
|---|---|
| 匯入照片並保留中繼資料 | 前端、後端 API、資料庫 |

端點清單：前端、後端 API、資料庫。
```

# Rule 2 - 分析 Wave 必須依端點分析工作的依賴關係排序並依序執行

- Level: `MUST`
- 規劃時，每個已盤點端點必須至少有一個明確的分析步驟，並安排在某個 Wave。
- 若某分析工作需要另一端點分析的產出作為輸入，必須排在該前置工作完成後的 Wave；不可把有先後依賴的工作排在同一 Wave 平行執行。
- 只有彼此沒有未滿足前置依賴、可獨立開始的分析工作，才可安排在同一 Wave 平行執行；Wave 順序應能看出後續工作的依賴輸入。
- 執行時，必須依規劃的 Wave 順序委派；同一 Wave 可平行執行的工作才可並行啟動，後續 Wave 必須取得並提供計畫要求的前置分析產物。
- 規劃段落只描述分析對象、步驟、依賴及委派安排，不得代替後續端點分析產生設計結論；端點分析結論應由對應專責 Skill 寫入其分析產物。

## Good Example

- 這個例子是好的，因為前端與金流分析沒有前置依賴，可在 Wave 1 平行；後端需要兩者的結果，因此排入 Wave 2，而資料庫分析可獨立並行。

```md
Wave 1（平行）：
1. 前端分析：整理使用者操作流程。
2. 金流端分析：查核第三方金流介面。

Wave 2（平行）：
1. 後端分析：使用 Wave 1 的前端流程與金流介面結果。
2. 資料庫分析：依資料持久化需求進行，無須等待後端分析結果。
```

## Bad Example

- 這個例子不合格，因為後端分析需要前端流程，但被安排在同一 Wave，無法保證分析開始前已有必要輸入。

```md
Wave 1（平行）：
1. 前端分析：整理使用者操作流程。
2. 後端分析：依前端操作流程分析 API。
```
