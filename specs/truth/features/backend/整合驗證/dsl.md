# 後端 / 整合驗證 DSL

以公開 HTTP 操作與權威持久化狀態，逐步驗證顧客點餐及店家出餐旅程。

## 技術 DSL（測試落地參考）

## Given 句型

| DSL 句型 | Gherkin 參數 | Data Table 參數 | 預設參數 | 後端實作語意 |
| --- | --- | --- | --- | --- |
| `菜單有一項供應中且可選規格的餐點` | 無 | 不支援 | 無 | `使用 fixture`：建立供應中的餐點及有效規格；`權威狀態落地`：資料保存於測試資料庫。 |
| `顧客購物車有一項可用餐點` | 無 | 不支援 | 無 | `使用 fixture`：建立有效餐點並加入顧客購物車；`權威狀態落地`：購物車列與菜單關聯可讀回。 |
| `專案提供預設整合驗證命令與測試環境` | 無 | 不支援 | 無 | `使用 fixture`：使用 repository 預設測試環境與已記載的整合驗證入口；不要求額外服務或手動 UI。 |
| `顧客有一筆未付款訂單` | 無 | 不支援 | 無 | `使用 fixture`：建立未付款訂單；`權威狀態落地`：訂單及金額快照持久化。 |
| `店家有一筆已付款且狀態為「已建立」的訂單` | 無 | 不支援 | 無 | `使用 fixture`：建立已付款且可接單的訂單；`權威狀態落地`：付款與訂單狀態可由店家 API 讀取。 |
| `店家有一筆狀態為「已接單」的訂單` | 無 | 不支援 | 無 | `使用 fixture`：建立已接單訂單；`權威狀態落地`：目前狀態已保存。 |
| `店家有一筆狀態為「出餐中」的訂單` | 無 | 不支援 | 無 | `使用 fixture`：建立出餐中訂單；`權威狀態落地`：目前狀態已保存。 |
| `顧客購物車有一項其後已停止供應的餐點` | 無 | 不支援 | 無 | `權威狀態落地`：先建立購物車列，再將關聯餐點設為停止供應；確保建單時可重新驗證最新狀態。 |

## When 句型

| DSL 句型 | Gherkin 參數 | Data Table 參數 | 預設參數 | 後端實作語意 |
| --- | --- | --- | --- | --- |
| `顧客將餐點加入購物車` | 無 | 不支援 | 無 | `怎麼做`：送出一次顧客加購請求；`權威狀態落地`：成功時購物車列保存；`回寫`：保存回應供 Then 驗證。 |
| `顧客建立訂單` | 無 | 不支援 | 無 | `怎麼做`：送出一次建單請求；`權威狀態落地`：成功時建立訂單與伺服器計算的金額快照；`回寫`：保存訂單識別與回應。 |
| `顧客以與實際應付金額不同的金額建立訂單` | 無 | 不支援 | 無 | `怎麼做`：送出含相容金額欄位且與伺服器計價不同的一次建單請求；`權威狀態落地`：仍以菜單與規格資料計算 snapshot；`回寫`：保存訂單結果；`不必查`：不可寫入客戶端金額。 |
| `團隊執行預設整合驗證` | 無 | 不支援 | 無 | `怎麼做`：以 techstack 記載的預設命令執行整合測試入口；`權威狀態`：使用預設 CI-compatible memory DB/harness；`回寫`：保留退出狀態與測試結果。 |
| `顧客付款成功` | 無 | 不支援 | 無 | `怎麼做`：送出一次付款操作；`權威狀態落地`：付款結果及付款狀態由支付服務契約保存；`回寫`：保存回應。 |
| `店家接單` | 無 | 不支援 | 無 | `怎麼做`：送出一次接單操作；`權威狀態落地`：訂單狀態轉為已接單；`回寫`：保存回應。 |
| `店家開始出餐` | 無 | 不支援 | 無 | `怎麼做`：送出一次開始出餐操作；`權威狀態落地`：訂單狀態轉為出餐中；`回寫`：保存回應。 |
| `店家完成訂單` | 無 | 不支援 | 無 | `怎麼做`：送出一次完成訂單操作；`權威狀態落地`：訂單狀態轉為已完成；`回寫`：保存回應。 |

## Then 句型

| DSL 句型 | Gherkin 參數 | Data Table 參數 | 預設參數 | 後端實作語意 |
| --- | --- | --- | --- | --- |
| `購物車包含該餐點及有效選項` | 無 | 不支援 | 無 | `必查`：`權威狀態`：購物車列含所選餐點與規格；`再讀確認`：重新讀取 cart API 確認。 |
| `訂單建立成功且保存建立時金額快照` | 無 | 不支援 | 無 | `必查`：`呈現結果`：建單成功；`權威狀態`：訂單與明細快照已持久化；`再讀確認`：查詢值與建立時價格一致。 |
| `付款狀態更新為「已付款」` | 無 | 不支援 | 無 | `必查`：`呈現結果`：付款成功；`權威狀態`：付款及訂單付款狀態更新；`再讀確認`：查詢仍顯示已付款。 |
| `訂單金額維持建立時快照` | 無 | 不支援 | 無 | `必查`：`權威狀態`：付款前後訂單金額及明細快照一致；`不該發生`：付款不得重算歷史金額。 |
| `顧客查詢時看到與店家一致的狀態` | 無 | 不支援 | 無 | `必查`：`跨視角`：顧客查詢與店家訂單讀取顯示相同狀態；`權威狀態`：兩者對應同一筆訂單。 |
| `系統拒絕建立訂單且不產生新訂單` | 無 | 不支援 | 無 | `必查`：`呈現結果`：建單遭拒且無新識別；`權威狀態`：訂單數不增加；`不該發生`：購物車不被清除。 |
| `訂單金額依伺服器菜單價格計算` | 無 | 不支援 | 無 | `必查`：`權威狀態`：total 由建立時菜單與規格價格計算；`不該發生`：不採信 request amount。 |
| `客戶端提供的金額不會改變訂單快照` | 無 | 不支援 | 無 | `必查`：`權威狀態`：持久化 order/item snapshot 等於 server 計價結果；`不該發生`：request amount 不落地。 |
| `整合測試在預設 CI 環境完成並回報執行結果` | 無 | 不支援 | 無 | `必查`：預設整合測試入口可執行並回報可判讀的結果/exit status；不新增未規定的時間門檻。 |
