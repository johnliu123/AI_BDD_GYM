# UI Plan：點餐系統第四迭代－店家管理與出餐流程

- **來源規格**：[功能規格：店家管理與出餐流程](./spec.md)
- **系統分析計畫**：[plan.md](./plan.md)
- **互動雛形**：[prototype/index.html](prototype/index.html)

## 範疇

- **分析邊界**：店家後台 UI 與顧客查詢狀態同步示意；假資料，不設計 OpenAPI schema 或 DBML。
- **涵蓋需求部位**：User Story 1–4；FR-001–FR-015；全域 FR-010–FR-013；BR-001–BR-003；SC-001–SC-006。
- **設計前提**：
  - 店家頁以「廚房／櫃台看板」為主；不接 menu 維護。
  - 雛形以 localStorage 模擬 token 與訂單狀態轉換。
  - 顧客查詢區塊可切換假訂單狀態，示範 US4。

## 畫面與流程

**tasks 機器錨點**：`ui-plan:§畫面與流程→店家訂單看板`、`→狀態篩選`、`→訂單詳情與快照金額`、`→接單`、`→開始出餐`、`→完成訂單`、`→店家憑證錯誤`、`→顧客查詢狀態同步`、`→狀態與邊界（雛形須可見）`

| 畫面 | 檔案 | 目的 |
|---|---|---|
| 店家看板 | `index.html` | 列表、篩選、詳情、動作按鈕 |
| 顧客查詢示意 | `index.html` | 輸入編號顯示動態 status_label |

### 店家訂單看板

- **觸發**：進入店家頁且 token 有效。
- **步驟**：顯示訂單卡片（編號、狀態、時間、總額）→ 點選開詳情。
- **追溯**：US1、FR-001、SC-001。

### 狀態篩選

- **觸發**：選擇「全部／已建立／已接單／出餐中／已完成」。
- **步驟**：列表僅顯示符合狀態的訂單。
- **追溯**：US1、FR-003。

### 訂單詳情與快照金額

- **觸發**：選取一筆訂單。
- **步驟**：顯示明細、單價、項目金額、總額（假資料固定快照，不隨「菜單漲價」變動）。
- **追溯**：US1 情境 2、4；FR-002、FR-012、SC-006。

### 接單

- **觸發**：詳情中狀態為「已建立」。
- **步驟**：按「接單」→ 狀態變「已接單」→ toast 成功。
- **追溯**：US2、FR-004、SC-002。

### 開始出餐

- **觸發**：狀態為「已接單」。
- **步驟**：按「開始出餐」→ 狀態「出餐中」。
- **追溯**：US3 情境 1、FR-007、SC-003。

### 完成訂單

- **觸發**：狀態為「出餐中」。
- **步驟**：按「完成訂單」→ 狀態「已完成」；按鈕隱藏或 disabled。
- **追溯**：US3 情境 2、FR-008、SC-003。

### 店家憑證錯誤

- **觸發**：清空 token 或輸入錯誤 token。
- **步驟**：顯示「店家憑證無效」，不顯示訂單列表。
- **追溯**：US1 情境 3、FR-010、SC-005。

### 顧客查詢狀態同步

- **觸發**：在查詢區輸入本雛形訂單編號。
- **步驟**：顯示與看板相同的 `status_label` 與快照金額。
- **追溯**：US4、FR-014、SC-004。

### 狀態與邊界（雛形須可見）

- 「已建立」不可直接「完成」；按鈕依狀態顯示。
- 「已完成」不可再變更狀態。
- 非法操作顯示錯誤 toast，狀態不變。

## 實作

- 正式前端：新增 `MerchantOrdersPage.jsx`、`merchantOrderApi.js`（`X-Merchant-Token`）；`App.jsx` 提供進入店家頁連結（hash 或 router）。擴充 `OrderLookupPage` 顯示 API 回傳之 `status_label`。
- 雛形：`prototype/assets/app.js` 假訂單陣列 + localStorage token。

## 驗證

- 走查：篩選待接單 → 接單 → 出餐 → 完成 → 顧客查詢區確認狀態一致。
- 錯誤 token 看不到列表。
- 雛形與 spec US1–US4 驗收情境對照。
