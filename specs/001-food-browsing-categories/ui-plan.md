# UI Plan：餐點瀏覽與分類

- **來源規格**：[spec.md](./spec.md)
- **系統分析計畫**：[plan.md](./plan.md)
- **互動雛形**：[prototype/index.html](./prototype/index.html)

## 範疇

- **分析邊界**：前端與使用者介面；不含 API、資料庫實作或後台管理功能。
- **涵蓋需求部位**：顧客瀏覽餐點、查看名稱、圖片、價格及分類，且資訊需對應至正確餐點。
- **設計前提（來自 plan／規格）**：
  - 本迭代僅包含顧客瀏覽餐點與分類，不納入購物車、訂單、付款或店家管理。
  - 每筆餐點皆必須顯示名稱、圖片、價格與分類。
  - 缺少圖片、價格或分類時，雛形需顯示空值狀態，而不是偽造或隱藏資料。
  - 排序、篩選與分區呈現方式還未由規格確認，因此 UI 不提前假設複雜篩選邏輯，以單一菜單列表為主流展示。

## 畫面與流程

| 畫面 | 檔案 | 目的 | 主要區塊 |
|---|---|---|---|
| 菜單瀏覽頁 | `prototype/index.html` | 顯示所有餐點與分類 | 頁首標題、分類篩選、餐點卡片、空狀態 |

### 餐點瀏覽流程

- **觸發**：顧客開啟餐點瀏覽頁。
- **步驟**：頁面讀取菜單資料 → 依分類顯示篩選標籤 → 渲染餐點卡片 → 每張卡片顯示名稱、圖片、價格與分類。
- **追溯**：FR-001、FR-002、SC-001、SC-002

### 餐點資料失效處理

- **觸發**：資料缺少圖片、價格或分類欄位。
- **步驟**：顯示佔位圖片與「暫無資料」提示，保證 UI 不呈現錯誤餐點關聯。
- **追溯**：spec.md 中「邊界情況」與研究決策中的失敗處理。

### 狀態與邊界（雛形須可見）

- 一般菜單狀態：多筆餐點資料渲染完整列表。
- 空資料狀態：餐點資料不存在時顯示提示。
- 部分缺失狀態：缺少圖片或價格時仍保留卡片框架並標示空值。

## 實作

- **雛形技術**：靜態 HTML、CSS、JavaScript，使用假資料在前端本地渲染，且不呼叫正式 API。
- **正式前端（對齊 plan）**：React + TypeScript + Vite；使用資料驅動渲染，餐點列表與分類標籤作為獨立可重用元件。
- **視覺方向**：乾淨的餐飲展示風格，深底或淺底配色均可；使用卡片式布局、明確價格標示與類別標籤，讓顧客快速辨識餐點。
- **非目標**：購物車、訂單流程、管理後台、付款與分類搜尋設定。

## 驗證

- **Markdown**：每個需求部位都在畫面與流程中有對應；不包含 API 或資料模型程式碼細節。
- **雛形**：
  - 以瀏覽器開啟 `prototype/index.html`。
  - 確認所有卡片都顯示餐點名稱、圖片、價格與分類。
  - 切換分類篩選後，顯示項目與所選分類一致。
  - 當資料缺失時，佔位圖片與提示保持可見。
- **與 plan 一致**：只處理餐點瀏覽與分類，且不引入購物車、訂單或管理端 UI。
