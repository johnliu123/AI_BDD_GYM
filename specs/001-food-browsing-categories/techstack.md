# Tech Stack: 餐點瀏覽與分類

## 整體架構

本迭代採用一個前後端分離的簡單 Web 架構：前端使用 React + TypeScript + Vite，後端提供 REST JSON API 讀取分類與餐點資料；資料依關聯式資料表保存，僅支援讀取頁面構成的瀏覽流程，未納入購物車、訂單與店家管理功能。

## 技術堆疊

| 領域 | 採用技術／決策 | 責任與用途 | 研究決策依據 | 版本或限制 |
|---|---|---|---|---|
| 前端 | React + TypeScript + Vite | 建立餐點瀏覽介面並渲染名稱、圖片、價格與分類 | [前端顯示與資料取得](./research.md#前端顯示與資料取得) | React / Vite 版本尚未固定；使用當前 LTS 版本之前端工具鏈 |
| API | Node.js LTS + Express | 提供 `/api/menu` 等讀取餐點資料的 JSON 端點 | [API 契約與資料形狀](./research.md#api-契約與資料形狀) | Node.js 以 LTS 版本為主，具體版本待定 |
| 資料層 | 關聯式 SQL schema（`categories` + `menu_items`） | 儲存分類與餐點資料，保持餐點與分類關聯正確 | [資料儲存與關聯](./research.md#資料儲存與關聯) | MySQL / PostgreSQL / SQLite 可作為實作落地；本輪未指定特定 DB |
| 影像與價格 | URL / 路徑 + `img` 元素 + 十進位貨幣格式 | 顯示每筆餐點圖片和價格，避免前端自行計算價格 | [影像與價格呈現](./research.md#影像與價格呈現) | 幣別與格式待確認，價格顯示需與後端資料一致 |

## 架構與部署限制

- 本迭代只支援顧客瀏覽餐點與分類，不包含購物車、訂單、付款與店家管理功能。
- 分類排序、篩選方式、是否以分類分區呈現、價格幣別與格式，以及缺少欄位時的處理方式，仍待決定。
- 若採用外部圖片來源，必須在發送給前端前保證 URL 正確且讀取可用；禁止前端依資料欄位自行拼接價格。

## 尚未固定的版本與選項

- React、Vite、Node.js、Express 的具體套件版本尚未決定。
- SQL 資料庫供應商（MySQL / PostgreSQL / SQLite）尚未固定；本輪只確定需要關聯式資料結構。
- 顯示幣別與價格格式須由後續需求或設計確認，未納入本迭代已確認需求。
