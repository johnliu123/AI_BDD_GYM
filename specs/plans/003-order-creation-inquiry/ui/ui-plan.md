# UI Plan：點餐系統第三迭代－訂單建立與查詢

- **來源規格**：[功能規格：訂單建立與查詢](./spec.md)
- **系統分析計畫**：[plan.md](./plan.md)
- **互動雛形**：[prototype/](prototype/index.html)

## 範疇

- **分析邊界**：前端 UI 與訪客操作流程；涵蓋購物車確認送單、建立成功回饋、訂單編號查詢及錯誤態。使用假資料，不設計 API 或資料表。
- **涵蓋需求部位**：User Story 1、User Story 2；FR-001–FR-009；全域 FR-010、FR-011；BR-001–BR-003；SC-001–SC-006。
- **設計前提**：
  - 沿用 002 訪客 session 模型；前端不持有 session ID。
  - 送單前顯示的總額為示意；正式金額以伺服器建立訂單回應為準。
  - 購物車含不可用項目時，確認送單按鈕拒絕並提示先移除或修正。
  - 建單成功後購物車為空；雛形清空 local 狀態。
  - 查詢僅能檢視「本雛形工作階段」曾建立的訂單；切換 session 模擬時查不到舊編號。

## 畫面與流程

**tasks 機器錨點**：`ui-plan:§畫面與流程→確認送單`、`→拒絕不可用購物車送單`、`→訂單建立成功`、`→查詢訂單狀態`、`→查無訂單`、`→狀態與邊界（雛形須可見）`

| 畫面 | 檔案 | 目的 |
|---|---|---|
| 菜單／購物車 | `index.html` | 沿用 002 流程加入餐點並管理 cart |
| 確認送單 | `index.html` | 自 cart 進入確認、送出 |
| 訂單結果 | `index.html` | 顯示訂單編號、狀態、快照明細 |
| 訂單查詢 | `index.html` | 輸入編號查詢 |

### 確認送單

- **觸發**：購物車有可用項目時選擇「確認送單」。
- **步驟**：顯示摘要（餐點、規格、數量、示意總額）→ 確認 → 假資料建立訂單 → 導向訂單結果並清空 cart。
- **追溯**：US1、FR-001、FR-003、FR-006、SC-001、SC-006。

### 拒絕不可用購物車送單

- **觸發**：cart 含不可用項目或僅不可用／空車時按送單。
- **步驟**：顯示錯誤、不產生訂單、cart 不變。
- **追溯**：US1 情境 2–3、FR-004、FR-005、SC-003。

### 訂單建立成功

- **觸發**：送單成功。
- **步驟**：顯示 order_number、狀態「已建立」、明細與快照金額；提供查詢入口。
- **追溯**：US1 情境 1、FR-002、SC-001、SC-002。

### 查詢訂單狀態

- **觸發**：輸入訂單編號查詢。
- **步驟**：本 session 曾建立的訂單顯示狀態與快照明細；即使雛形菜單漲價，查詢仍顯示建立當下金額。
- **追溯**：US2 情境 1–2、FR-008、FR-009、SC-005。

### 查無訂單

- **觸發**：錯誤編號或切換 session 後查舊編號。
- **步驟**：統一查無提示，不顯示他人訂單。
- **追溯**：US2 情境 3–4、FR-010、SC-005。

### 狀態與邊界（雛形須可見）

- 空 cart 無法送單；不可用項目阻擋送單但可刪除後再送。
- 雛形可模擬重複送單（同一 idempotency 示意）只產生一筆訂單。
- 建單後 cart 數量 badge 為 0。

## 實作

- 正式前端：擴充 `CartPage.jsx` 或新增 `CheckoutPage.jsx`、`OrderLookupPage.jsx`；`orderApi.js` 對齊 OpenAPI；送單前 `GET /api/cart` 取 CSRF。
- 雛形：`prototype/assets/app.js` 以 localStorage 模擬 session 訂單列表與快照。

## 驗證

- 走查：加入餐點 → 確認送單 → 見編號 → 查詢 → 切 session 查無。
- 不可用項目與空 cart 拒絕送單。
- 雛形與 spec US1／US2 驗收情境對照表可於 tasks T0xx 引用。
