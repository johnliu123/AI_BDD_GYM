# UI Plan：點餐系統第二迭代－購物車與金額計算

- **來源規格**：[功能規格：購物車與金額計算](./spec.md)
- **系統分析計畫**：[plan.md](./plan.md)
- **互動雛形**：[prototype/](prototype/index.html)

## 範疇

- **分析邊界**：前端 UI 與訪客操作流程；涵蓋供應中餐點、規格選擇、購物車檢視與調整、最新價格呈現、空狀態、錯誤及訪客工作階段狀態。使用假資料展示介面，不設計 API、資料表或服務端實作。
- **涵蓋需求部位**：User Story 1、User Story 2；FR-001、FR-002、FR-003、FR-006、FR-007、FR-008；全域 FR-004、FR-005；BR-001、BR-002、BR-003；SC-001、SC-002、SC-003、SC-004、SC-005。
- **設計前提（來自 plan／規格）**：
  - 每個訪客工作階段使用伺服器簽發並透過 HttpOnly cookie 傳遞的識別；前端不讀取或自行提供工作階段識別。購物車依工作階段隔離，不提供登入、帳號綁定、跨瀏覽器合併或跨裝置同步。
  - 訪客工作階段失效後不顯示其他工作階段的購物車；若介面得知已進入新工作階段，呈現新的空購物車，不承諾恢復或合併先前購物車。服務端預設 **idle 24 小時、absolute 7 天**（spec Q10）；UI 在偵測到新 session／空車時提示工作階段已更新。
  - 餐點供應狀態、目前餐點價格、規格加價及金額由服務端權威確認與計算；雛形使用假資料示意，不把前端計算視為正式計價。
  - 正式規格群組與選項由既有菜單能力提供；正式金額以十進位字串提供，前端只呈現服務端結果，不轉成 JavaScript `Number` 計價。
  - 餐點具有規格群組時，每個群組都必須且只能選一項；初始不預選，缺少任一群組選項時拒絕加入且購物車不變。沒有規格群組的餐點不受此選擇限制，可直接加入。
  - 每個規格群組使用獨立單選控制項；項目數量為正整數，刪除以獨立操作呈現。
  - 正式金額與精度由後端固定，雛形僅以數值作為流程示意，不自行宣稱幣別符號、千分位或精度承諾。
  - 相同餐點與相同規格每次加入均建立獨立購物車項目；雛形中重複加入會新增一筆，不合併數量。

## 畫面與流程

**tasks 機器錨點**（章節 `§畫面與流程` → 下方 `###` 小節標題）：`ui-plan:§畫面與流程→選擇規格並加入供應中餐點`、`→拒絕未供應餐點`、`→檢視與管理購物車`、`→不可用購物車項目`、`→顯示最新價格`、`→訪客工作階段`、`→計價錯誤`、`→狀態與邊界（雛形須可見）`（勿使用不存在的合併小節名）。

| 畫面 | 檔案 | 目的 | 主要區塊 |
|---|---|---|---|
| 菜單與餐點規格 | `index.html` | 瀏覽供應中餐點、選擇各規格群組選項及加入購物車 | 餐廳導覽、分類、餐點卡、規格對話框、購物車入口 |
| 購物車 | `index.html` | 檢視項目與最新金額、修改正整數數量或刪除項目 | 購物車清單、項目價格、總額、價格更新提示、空狀態 |
| 訪客工作階段狀態 | `index.html` | 顯示訪客購物流程；工作階段更新時呈現新工作階段的空購物車 | 訪客狀態標示、空購物車、工作階段更新提示 |
| 計價錯誤狀態 | `index.html` | 呈現最新價格暫時無法取得及重試操作 | 錯誤提示、重試操作；不沿用舊總額 |

### 選擇規格並加入供應中餐點

- **觸發**：在菜單選擇餐點並開啟規格選擇。
- **步驟**：開啟餐點選擇時各群組皆未預選 → 每個規格群組各選一項 → 確認選項與示意單價 → 加入購物車 → 顯示成功回饋與更新後的購物車數量。若缺少任何群組選項，加入操作須拒絕，標示未完成群組並維持購物車內容與數量不變；餐點沒有規格群組時可直接加入。
- **追溯**：User Story 1、FR-001、FR-002、FR-004、FR-005、BR-001、BR-002、SC-001、SC-002、SC-004。

### 拒絕未供應餐點

- **觸發**：嘗試加入標記為未供應的餐點。
- **步驟**：雛形以拒絕提示回應，購物車內容與數量維持不變。
- **追溯**：User Story 1、FR-003、SC-004。

### 檢視與管理購物車

- **觸發**：選擇「購物車」導覽。
- **步驟**：檢視餐點、所選規格、數量、項目金額與總額 → 以步進控制或正整數輸入修改可用項目數量 → 項目金額與總額依目前假資料重算；選擇刪除以移除項目。失效項目保留並標示不可用、不顯示金額、不計入總額、停用數量控制但仍可刪除。最後一項刪除後顯示空購物車與零總額。
- **追溯**：User Story 2、FR-004、FR-005、FR-006、FR-007、FR-008、BR-001、BR-003、SC-002、SC-003、SC-005。

### 不可用購物車項目

- **觸發**：餐點加入後停止供應，或購物車所選規格選項被停用。
- **步驟**：保留該購物車項目並標示不可用；省略單價與項目金額，不納入總額；停用數量修改，保留刪除操作。其他可用項目照常顯示及計價。
- **追溯**：User Story 2、FR-008、SC-005；API `getCart`、`updateCartItemQuantity`、`deleteCartItem`。

### 顯示最新價格

- **觸發**：雛形情境控制更新菜單假資料，或再次查看購物車。
- **步驟**：購物車以目前假資料更新項目與總額，並在受影響項目旁顯示價格已變更提示；不把加入當下價格當作目前計價依據。
- **追溯**：User Story 2、FR-005、FR-006、FR-007、BR-001、SC-002、SC-003。

### 訪客工作階段

- **觸發**：訪客開啟購物車，或雛形情境控制切換至另一工作階段／模擬目前工作階段逾期。
- **步驟**：只顯示目前訪客工作階段的購物車；切換至不同工作階段時，其購物車與數量互相隔離。模擬逾期後進入新的空購物車並提示工作階段已更新，不顯示或合併舊工作階段內容，也不提供登入或帳號恢復入口。
- **追溯**：User Story 1、User Story 2、FR-004、FR-006、SC-004。

### 計價錯誤

- **觸發**：雛形情境控制模擬最新價格暫時無法取得。
- **步驟**：不顯示舊總額作為最新結果，提供重試。
- **追溯**：User Story 2、FR-005、FR-006、SC-002。

### 狀態與邊界（雛形須可見）

- 供應中與未供應餐點；未供應餐點加入遭拒且購物車不變。
- 餐點具有規格群組時，各群組初始皆未選；每個群組各自單選且必須完成。缺少任一群組選項時顯示欄位錯誤與整體回饋、拒絕加入且購物車不變；沒有規格群組的餐點仍可直接加入。
- 數量僅接受正整數，無效輸入不會以零或負數移除項目。
- 有項目、空購物車與零總額；刪除使用明確操作。
- 菜單價格變更後顯示最新示意金額與變更提示；計價失敗時不沿用舊總額。
- 購物車項目餐點停供或所選規格失效後，確認項目保留、不可用標記、金額省略與總額排除；數量不可修改但刪除可用。
- 不同訪客工作階段各自只顯示自己的購物車；切換工作階段不沿用另一工作階段的項目或數量。
- 模擬工作階段逾期後顯示工作階段更新提示與新空購物車；不呈現登入、身份驗證、帳號恢復或跨工作階段合併操作。
- 相同餐點及規格重複加入時，雛形新增獨立項目；每筆項目保留自己的數量與識別。
- 金額為假資料的無幣別數值，不暗示正式幣別、精度或序列化格式。

## 實作

- **雛形技術**：單一靜態 `index.html`，共用 `assets/styles.css` 與 `assets/app.js`；使用本機假資料與 `localStorage` 分別模擬訪客工作階段的購物車及重新整理後的演示狀態，不呼叫正式 API。雛形儲存方式不代表正式工作階段識別機制。
- **正式前端（對齊 plan）**：以既有 React + JavaScript + Vite 呈現菜單與購物車流程；瀏覽器自動攜帶伺服器簽發的 HttpOnly 訪客工作階段 cookie，前端不讀取或保存工作階段識別。前端呈現服務端回傳的目前價格與計算結果，不自行決定權威金額。
- **視覺方向**：以餐廳菜單攝影作為辨識主軸，搭配清楚的餐點分類、規格選擇與固定易尋的購物車導覽；採柔和紙白底色、墨綠文字及番茄紅操作色。使用精簡狀態提示，避免把畫面做成規格說明頁。
- **非目標**：登入／註冊、API 或資料庫設計、正式計價、結帳、訂單、付款、稅金、運費、折扣、店家管理，以及決定幣別／精度格式。

## 驗證

- **Markdown**：確認需求部位皆由流程或可見狀態追溯；連結 `spec.md` 與 `plan.md`；Q9/FR-004 的匿名訪客工作階段與購物車隔離一致；未定事項維持未定；無 API、資料表或後端交易設計。
- **雛形**：
  - 直接開啟 `prototype/index.html`，選擇具有多個規格群組的餐點，確認所有群組初始未預選；不選任何群組便嘗試加入，確認指出未完成群組、操作被拒且購物車數量與內容不變。
  - 只完成多個規格群組中的部分群組後再次嘗試加入，確認仍遭拒且購物車不變；為每個群組各選一項後加入成功，購物車顯示所選規格。
  - 選擇沒有規格群組的餐點，確認不需選項即可加入購物車。
  - 嘗試加入未供應餐點，確認有拒絕回饋且購物車不變。
  - 開啟購物車，修改數量、輸入無效數量、刪除項目，確認金額更新及最後一項刪除後的空狀態。
  - 先加入餐點，再以雛形情境控制停用餐點或所選規格；確認項目仍顯示不可用、不顯示金額且不計總額，數量操作受阻但刪除成功。
  - 使用雛形情境控制更新菜單價格，確認購物車呈現最新示意金額與變更提示；模擬計價錯誤並重試。
  - 在第一訪客工作階段加入餐點後切換至另一訪客工作階段，確認購物車互相隔離；切回第一工作階段時只顯示其原有項目。
  - 模擬工作階段逾期，確認畫面提示工作階段已更新並顯示新的空購物車，不提供登入／恢復帳號或合併購物車入口。
  - 重複加入相同餐點與規格，確認購物車新增獨立項目且不合併數量。
  - 確認版面於窄螢幕可操作，且金額未出現幣別或精度承諾。
- **與 plan 一致**：沿用 React + JavaScript + Vite 作為正式前端方向；匿名購物車以伺服器簽發的 HttpOnly 訪客工作階段 cookie 隔離；價格及供應狀態以服務端為權威；不納入登入、帳號、跨裝置同步、結帳、訂單、付款或店家管理。
